# Мам, я сам!

Лендинг концепт-курса по финансовой грамотности и самостоятельности для подростков 5–8 классов. Статический сайт на русском языке: один HTML-документ со встроенными стилями и скриптом, а также исходные `style.css` и `script.js`, из которых эти блоки синхронизируются.

## Структура

- `index.html` — лендинг: тарифы, программа, FAQ, форма заявки и раздел политики данных.
- `script.js` — прогресс чтения, выбор тарифа, отправка формы, декоративные эффекты.
- `style.css` — все стили сайта.
- `scripts/check-site.mjs` — статические проверки без внешних зависимостей.
- `scripts/sync-assets.mjs` — переносит `style.css` и `script.js` во встроенные блоки `index.html`.
- `content/telegram-autopost-plan.md` — правила будущего автопостинга Telegram.
- `.github/workflows/pages.yml` — статические проверки и публикация сайта на GitHub Pages.
- `.github/workflows/checks.yml` — проверки на push, pull request и ручной запуск.
- `.github/workflows/opencode.yml` — автоматическое обслуживание с предложением изменений через PR для ручной проверки владельцем. Workflow не сливает PR автоматически; запуск агента ограничен shell-таймаутом.

## Локальный просмотр

Откройте `index.html` в браузере или запустите простой сервер из корня проекта:

```bash
python3 -m http.server 8000
```

Затем откройте `http://localhost:8000/`.

## Проверки

В проекте нет сборки и npm-зависимостей. Нужен только Node.js 20+:

```bash
node --check script.js
node scripts/check-site.mjs
```

Скрипт проверяет совпадение встроенных блоков с `style.css` и `script.js`, обязательные поля и `method="post"` формы, уникальность `id`, соответствие тарифов, защиту Telegram-редиректа, наличие политики данных, локальные ссылки и якоря, ARIA-связи и отсутствие похожих на секреты строк. Те же проверки запускаются в GitHub Actions на push, pull request и перед публикацией.

## Как менять стили и скрипт

`style.css` и `script.js` — источники истины. После их изменения выполните:

```bash
node scripts/sync-assets.mjs
node --check script.js
node scripts/check-site.mjs
```

Синхронизация нужна, потому что `index.html` остаётся самодостаточным: так сайт работает даже при публикации одного HTML-файла. Проверка не даст встроенным блокам разойтись с исходниками.

## Форма заявки

Форма на `index.html` отправляет JSON в Supabase Edge Function `signup-request`. Используется публичный publishable key, предназначенный для клиента; ключ с повышенными правами и другие секреты в репозитории не хранятся. Заявка содержит имя, телефон, email, комментарий, выбранный тариф, признак согласия, honeypot-поле и время открытия страницы.

Клиентская защита:

- проверка обязательных полей и согласия до отправки, включая защиту от имени/email из одних пробелов;
- ограничение длины полей и обрезка пробелов перед отправкой;
- honeypot против простых ботов;
- защита от повторной отправки, пока запрос ещё выполняется;
- таймаут запроса 15 секунд с понятным сообщением;
- понятные русские сообщения при сетевой ошибке и ответе 429;
- разрешён редирект только на `https://t.me` и `https://telegram.me`;
- `method="post"` и `action="#signup"`, чтобы при отключённом или сломанном JS данные формы не попадали в URL;
- `noscript`-подсказка с контактом в Telegram;
- при ошибке кнопка снова становится активной.

### Особенность пробного тарифа

В интерфейсе и коде пробный тариф называется `trial_3d`, потому что продукт даёт 3 дня. В запросе к Supabase по-прежнему отправляется исторический идентификатор `trial_7d` (`TRIAL_PLAN_WIRE_ID` в `script.js`), чтобы не сломать существующий контракт Edge Function. Перед переименованием идентификатора на стороне backend нужно проверить Edge Function и данные: возможно, `trial_7d` также задаёт длительность доступа.

## Публикация

Workflow `Deploy to GitHub Pages` запускается при push в `main` или вручную. Он:

1. выполняет `node --check` и статические проверки;
2. копирует `index.html`, `style.css`, `script.js` (и каталог `admin`, если он появится) в `_site`;
3. публикует артефакт на GitHub Pages.

Если проверка не прошла, публикация не выполняется. Откат: вернуть предыдущий коммит в `main` через revert и дождаться повторного запуска workflow.

Автоматизация предложения PR намеренно исключает каталог `.github`, чтобы агент не менял CI без отдельного контроля. Поэтому изменения `checks.yml`, `pages.yml` и `opencode.yml` нужно применить отдельным обычным PR или вручную. Без них сайт продолжит работать, потому что стили и скрипт встроены, но новые проверки не будут запускаться автоматически.

## Безопасность и данные

- Не добавляйте в репозиторий ключи с повышенными правами, секретные ключи Supabase, токены GitHub, пароли или приватные ключи.
- Публичный publishable key в `script.js` не является секретом доступа к базе: права должны ограничиваться Edge Function и RLS на стороне Supabase.
- Реальные заявки, платежи, доступы и журналы не хранятся в репозитории.
- Политика данных описывает текущее поведение сайта; перед юридически значимым запуском её нужно проверить с владельцем проекта.
